## Anatomy

Import and assemble the component:

```tsx
import { Drawer } from "@raystack/apsara";

<Drawer side="right">
  <Drawer.Trigger />
  <Drawer.SwipeArea />
  <Drawer.Content>
    <Drawer.Header>
      <Drawer.Title />
      <Drawer.Description />
    </Drawer.Header>
    <Drawer.Body />
    <Drawer.Footer />
  </Drawer.Content>
</Drawer>
```

The indent parts are optional. They wrap your app:

```tsx
<Drawer.Provider>
  <Drawer.IndentBackground />
  <Drawer.Indent>{/* your app, with its drawers */}</Drawer.Indent>
</Drawer.Provider>
```

## Usage

Pick the edge it enters from, then decide who owns its open state.

### Basic

A drawer slides in from the edge named by `side` and traps focus while open.

<Demo data={basicDemo} />

### Positioning

The Drawer can slide in from different sides of the screen. Swipe-to-dismiss is automatically configured based on the `side` prop.

<Demo data={positionDemo} />

### Controlled

Pass `open` with `onOpenChange` to own the state. Do this when the drawer has to open from elsewhere on the page, or stay open until a save completes.

<Demo data={controlledDemo} />

### Swipe to open

`Drawer.SwipeArea` is an invisible strip along a screen edge. Users drag from it to open the drawer. It sits on the edge named by `side`. Pass `swipeDirection` to change the drag direction that opens it. The swipe area ignores pointer events while the drawer is open.

<Demo data={swipeAreaDemo} />

### Forms and the phone keyboard

`Drawer.Content` handles the on-screen keyboard on phones. When an input inside the drawer gets focus and the keyboard opens, the drawer scrolls to keep the input visible. You do not need to set anything up. Base UI also sets `--drawer-keyboard-inset` on the `drawer-viewport` slot while the keyboard is open. Use `var(--drawer-keyboard-inset, 0px)` to lift a pinned footer above the keyboard.

<Demo data={keyboardDemo} />

### Indent

Wrap your app in `Drawer.Provider`, then put `Drawer.IndentBackground` and `Drawer.Indent` at the top of the tree. While any drawer inside the provider is open, the indent scales down and rounds its top corners, and the background shows behind it. Both parts get a `data-active` attribute while a drawer is open. The effect follows the swipe as users drag the drawer closed. With reduced motion, the indent does not move.

<Demo data={indentDemo} />

Every rendered part carries a stable `data-slot` attribute for [styling and testing](/docs/styling#with-data-slot):

| `drawer-header` | The `Drawer.Header` container |
| `drawer-title` | The `Drawer.Title` element |
| `drawer-description` | The `Drawer.Description` element |

| `drawer-indent-background` | The `Drawer.IndentBackground` layer |

## Accessibility

- Uses `role="dialog"` with `aria-modal="true"`.
- Focus is trapped within the drawer and restored on close.
- Supports dismissal with Escape key and swipe gestures.
- Default `aria-label` is `"Drawer"`. Pass `aria-label` or `aria-labelledby`
  on `Drawer.Content` to give the dialog a meaningful name.
- Close button label defaults to `"Close"`. Override with the `closeLabel`
  prop for localisation or context-specific copy (e.g. `"Close settings"`).
- Respects motion preferences: drawer slide motion is enabled only when
  `prefers-reduced-motion: no-preference`.
