## Anatomy

Import and assemble the component:

```tsx
import { Menu } from '@raystack/apsara'

<Menu>
  <Menu.Trigger />
  <Menu.Content>
    <Menu.Item />
  </Menu.Content>
</Menu>
```

## Usage

Beyond the plain case, items can carry icons, sit in groups, nest into submenus, and narrow down as someone types.

### Basic usage

A trigger and a list of items. The menu opens on click and closes on select, Escape, or an outside click.

<Demo data={basicDemo} />

### With icons

You can add icons to the menu items. Supports both leading and trailing icons.

<Demo data={iconsDemo} />

### With groups and labels

Organize related menu items into sections with descriptive headers.

<Demo data={customDemo} />

### Submenu

Use `Menu.Submenu`, `Menu.SubmenuTrigger`, and `Menu.SubmenuContent` to create nested menus with multiple levels.

<Demo data={submenuDemo} />

### Checkbox items

Use `Menu.CheckboxItem` for a setting that turns on or off. Clicking it toggles the check mark and keeps the menu open. Pass `checked` and `onCheckedChange` to control it.

<Demo data={checkboxDemo} />

### Radio items

Wrap `Menu.RadioItem` parts in a `Menu.RadioGroup`. Only one item in the group is checked at a time. Clicking an item keeps the menu open.

<Demo data={radioDemo} />

### Link items

Use `Menu.LinkItem` to navigate. It renders an `<a>` element. The menu stays open on click by default. Pass `closeOnClick` to close it, for example with client-side routing.

To use a router link, pass it to `render`. The item keeps its layout and icons.

```tsx
<Menu.LinkItem render={<NextLink href="/projects" />}>Projects</Menu.LinkItem>
```

<Demo data={linkDemo} />

### Autocomplete

Pass `autocomplete` to the Menu root. Each menu manages its own autocomplete state.

- **`autocompleteMode="auto"`** is the default. Items filter as the user types. Each item matches by its `value` prop, or by its children text when it has no `value`. Matching ignores case and accents.
- **`autocompleteMode="manual"`** leaves filtering to you. Do it in `onInputValueChange`.
- **Submenus** opt in separately: pass `autocomplete` to `Menu.Submenu`.

<Demo data={autocompleteDemo} />

### Linear inspired Menu

This is a Linear-inspired menu component that supports custom filtering and displays nested options. Users can search through all nested items using a single input field.

To closely replicate Linear-style filtering, the filtering logic should include result ranking. Using a utility like [match-sorter](https://www.npmjs.com/package/match-sorter) can help achieve this by sorting filtered results based on relevance.

<Demo data={linearDemo} />

### Controlled

Pass `open` with `onOpenChange` to own the state. Do this when a keyboard shortcut or another control has to open the menu.

<Demo data={controlledDemo} />

## API Reference

The root element is the parent component that holds the menu. Using the `autocomplete` prop, you can enable search functionality.

The button that triggers the menu.

Use the `render` prop to render a custom trigger element.

The container that holds the menu items. When autocomplete is enabled, renders an inline search input inside the popup with a search input.

Individual clickable options within the menu. Built on top of [Base UI Menu.Item](https://base-ui.com/react/components/menu).

### Submenu

Wraps a submenu root. Use with `Menu.SubmenuTrigger` and `Menu.SubmenuContent` to create nested menus.

Supports its own `autocomplete` prop to enable search functionality within the submenu independently from the parent menu.

<auto-type-table path="./props.ts" name="MenuSubMenuProps" />

### SubmenuTrigger

The trigger item for a submenu. Renders with a trailing chevron icon by default. Accepts `leadingIcon` and `trailingIcon` props.

When inside a searchable parent menu, the trigger matches by its `value` prop, or by its children text when it has no `value`. The root search does not search inside submenus.

<auto-type-table path="./props.ts" name="MenuSubTriggerProps" />

### SubmenuContent

The content container for a submenu. Shares the same API as `Menu.Content` with a default `sideOffset` of `2`.

## Accessibility

- Built on [Base UI Menu](https://base-ui.com/react/components/menu), following
  the [WAI-ARIA Menu pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menu/):
  the trigger exposes `aria-haspopup` and `aria-expanded`, the popup uses
  `role="menu"`, and items use `role="menuitem"`.
- Arrow keys move through items, Enter activates the highlighted item, Escape
  closes the menu and returns focus to the trigger, and ArrowRight/ArrowLeft
  open and close submenus.
- With `autocomplete`, the trigger has `aria-haspopup="dialog"` and the popup
  becomes a `role="dialog"` containing a search input (`role="searchbox"`,
  labelled by `searchPlaceholder`) and a `role="menu"` list. Items keep their
  menu roles. Focus stays in the input while arrow keys move the highlight.
  ArrowRight opens a highlighted submenu and moves focus to its first item, or
  to its own search input when it is searchable. Escape closes the submenu and
  returns focus to the parent input.
- `Menu.Label` must be wrapped in `Menu.Group` so the group is labelled via
  `aria-labelledby`.
- `Menu.CheckboxItem` uses `role="menuitemcheckbox"` and `Menu.RadioItem` uses
  `role="menuitemradio"`, both with `aria-checked`.
- `Menu.LinkItem` renders an `<a>` with `role="menuitem"`.
- In a searchable menu, `Menu.EmptyState` is a `role="status"` live region.
