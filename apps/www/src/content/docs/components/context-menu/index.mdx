## Anatomy

Import and assemble the component:

```tsx
import { ContextMenu } from '@raystack/apsara'

<ContextMenu>
  <ContextMenu.Trigger />
  <ContextMenu.Content>
    <ContextMenu.Item />
  </ContextMenu.Content>
</ContextMenu>
```

## Usage

A context menu opens on right-click or long press. Its contents are composed the same way as [Menu](/docs/components/menu).

### Basic usage

A simple context menu with basic functionality. Right-click the trigger area to open.

<Demo data={basicDemo} />

### With icons

You can add icons to the menu items. Supports both leading and trailing icons.

<Demo data={iconsDemo} />

### With groups and labels

Organize related menu items into sections with descriptive headers.

<Demo data={customDemo} />

### Submenu

Use `ContextMenu.Submenu`, `ContextMenu.SubmenuTrigger`, and `ContextMenu.SubmenuContent` to create nested menus with multiple levels.

<Demo data={submenuDemo} />

### Checkbox, radio, and link items

`ContextMenu.CheckboxItem`, `ContextMenu.RadioGroup`, `ContextMenu.RadioItem`, and `ContextMenu.LinkItem` work the same way as in [Menu](/docs/components/menu#checkbox-items). Checkbox and radio items keep the menu open on click. Link items render an `<a>` element.

<Demo data={selectionDemo} />

### Autocomplete

Pass `autocomplete` to the ContextMenu root. Each menu manages its own autocomplete state.

- **`autocompleteMode="auto"`** is the default. Items filter as the user types, matched against each item's `value` prop or its children text.
- **Submenus** opt in separately: pass `autocomplete` to `ContextMenu.Submenu`.

<Demo data={autocompleteDemo} />

### Empty state and status

`ContextMenu.EmptyState` shows its children only when the menu has no items, for example when nothing matches the search. `ContextMenu.Status` announces the number of matching items to screen readers while the search input has text. It is not visible.

<Demo data={emptyDemo} />

### Controlled

Pass `open` with `onOpenChange` to own the state. Do this when the menu has to close on something other than a selection, or when only one menu may be open at a time.

<Demo data={controlledDemo} />

## API Reference

The ContextMenu component is composed of several parts, each with their own props.

### Root

The root element is the parent component that holds the context menu. Using the `autocomplete` prop, you can enable search functionality.

### Trigger

The area that opens the context menu on right-click or long press. Renders a `<div>` element.

<auto-type-table path="./props.ts" name="ContextMenuTriggerProps" />

### Content

The container that holds the menu items. When autocomplete is enabled, renders an inline search input inside the popup.

<auto-type-table path="./props.ts" name="ContextMenuContentProps" />

### Item

Individual clickable options within the menu. Built on top of [Base UI ContextMenu.Item](https://base-ui.com/react/components/context-menu).

Renders as a `role='option'` when used in an autocomplete menu. By default, the item's `children` text content is used for matching, which can be overridden by passing a `value` prop.

<auto-type-table path="./props.ts" name="ContextMenuItemProps" />

### CheckboxItem

A menu item that toggles a setting on or off. Renders a check mark before the label when checked.

<auto-type-table path="./props.ts" name="ContextMenuCheckboxItemProps" />

### RadioGroup

Groups related radio items and holds the selected value.

<auto-type-table path="./props.ts" name="ContextMenuRadioGroupProps" />

### RadioItem

A menu item that works like a radio button in a `ContextMenu.RadioGroup`. Renders a dot before the label when checked. The `value` prop is also used for search matching when it is a string.

<auto-type-table path="./props.ts" name="ContextMenuRadioItemProps" />

### LinkItem

A menu item that renders an `<a>` element. Pass a router link to `render` to use client-side routing.

<auto-type-table path="./props.ts" name="ContextMenuLinkItemProps" />

### Group

A way to group related menu items together. When filtering is active, the group wrapper is removed and items are rendered flat.

<auto-type-table path="./props.ts" name="ContextMenuGroupProps" />

### Label

Renders a label in a menu group. This component should be wrapped with ContextMenu.Group so the `aria-labelledby` is correctly set on the group element. Hidden when filtering is active.

<auto-type-table path="./props.ts" name="ContextMenuLabelProps" />

### Separator

Visual divider between menu items or groups. Hidden when filtering is active.

<auto-type-table path="./props.ts" name="ContextMenuSeparatorProps" />

### EmptyState

Content to show when the menu has no items. With `autocomplete`, it shows when nothing matches the search. The element stays in the DOM as a live region (`role="status"`), so screen readers announce it when it appears.

<auto-type-table path="./props.ts" name="ContextMenuEmptyStateProps" />

### Status

A live region that announces the number of matching items while the search input has text. It is visually hidden. It renders only in a searchable menu (`autocomplete`), and renders nothing otherwise.

<auto-type-table path="./props.ts" name="ContextMenuStatusProps" />

### Submenu

Wraps a submenu root. Use with `ContextMenu.SubmenuTrigger` and `ContextMenu.SubmenuContent` to create nested menus.

Supports its own `autocomplete` prop to enable search functionality within the submenu independently from the parent menu.

<auto-type-table path="./props.ts" name="ContextMenuSubMenuProps" />

### SubmenuTrigger

The trigger item for a submenu. Renders with a trailing chevron icon by default. Accepts `leadingIcon` and `trailingIcon` props.

When inside a searchable parent menu, the `value` prop can be used for autocomplete matching.

<auto-type-table path="./props.ts" name="ContextMenuSubTriggerProps" />

### SubmenuContent

The content container for a submenu. Shares the same API as `ContextMenu.Content` with a default `sideOffset` of `2`.

<auto-type-table path="./props.ts" name="ContextMenuSubContentProps" />

## Accessibility

- Built on [Base UI Context Menu](https://base-ui.com/react/components/context-menu):
  the popup uses `role="menu"` and items use `role="menuitem"`, following the
  [WAI-ARIA Menu pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menu/).
- Opens on right-click or long press (touch); focus moves into the menu when
  it opens and returns to the page when it closes with Escape.
- Arrow keys move through items, Enter activates the highlighted item, and
  ArrowRight/ArrowLeft open and close submenus.
- With `autocomplete`, the popup becomes a `role="dialog"` containing a search
  input, items render as `role="option"`, and focus stays in the input while
  arrow keys move the highlight, and Escape first closes an open submenu.
- `ContextMenu.Label` must be wrapped in `ContextMenu.Group` so the group is
  labelled via `aria-labelledby`.
- Checkbox items use `role="menuitemcheckbox"` and radio items use
  `role="menuitemradio"`, both with `aria-checked`. In a searchable menu they
  render as `role="option"` and keep `aria-checked`.
- `ContextMenu.EmptyState` and `ContextMenu.Status` are polite live regions.
